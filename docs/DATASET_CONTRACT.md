# Synthetic data contract

This document defines the versioned synthetic **Controle de Ocorrências** data used for
development and structural-safety evaluation. The generator, manifest loader, and evaluator
must agree with this contract; published numbers are produced by code, never typed into prose.

## What the data can establish

The synthetic sheets test whether the executable intake fails closed when a known table is
rendered with controlled layout variation, noise, missing content, and illegible fields. Every
sheet has generated truth, so the evaluator can trace a result through OCR, normalization,
review blockers, classification, routing, approval readiness, and export readiness.

The data does **not** establish handwriting accuracy on real people or real corporate forms.
Font-rendered writing is easier and less varied than human cursive. Synthetic labels also share
vocabulary and structure with the generator and rules, so classification results are not a
substitute for an independently labeled operational dataset.

The public corpus contains no copied company form, employee record, location, schedule, or real
incident. Names, units, dates, and occurrence text come from reviewed fictional generators.

## Version identities

Three identities are intentionally separate:

| Identity | Current value | Changes when |
|---|---|---|
| Generated content | `tier_c/v2` | Rendered truth, vocabulary, layout, or degradation changes |
| Manifest envelope | `tier_c-manifest/v2` | Paths, fields, canonicalization, or validation changes |
| Release corpus | `ssi-safety-corpus/v1` for release line `v1.1` | The committed release-input contract changes |

Changing generated bytes requires a new content version. A dependency or font update that
changes rasterization is not repaired by editing hashes; it starts a new versioned generation
and review cycle.

## Canonical datasets

The single source of truth is `CANONICAL_DATASETS` in
[`data/generators/tier_c.py`](../data/generators/tier_c.py).

| Dataset | Sheets | Seed | Profile | Purpose |
|---|---:|---:|---|---|
| `smoke` | 50 | 42 | balanced | Fast generator and evaluator checks |
| `bench-balanced` | 300 | 43 | balanced | Reference benchmark; its 45-sheet validation split feeds v1.1 safety evidence |
| `bench-operational` | 300 | 44 | operational | Non-release distribution diagnostic |
| `stress` | 1000 | 45 | balanced | Scale and robustness work outside normal CI |

Each dataset is assigned to `train`, `val`, and `test` with a deterministic 70/15/15 split.
Normal release work uses `bench-balanced/val`. Historical test freezes remain historical and
must not be redefined as current release inputs.

## Ground-truth model

Every `gt/<doc_id>.json` is validated against a strict schema with unknown keys rejected. It
contains:

- a stable `tc-NNNNNN` document ID and generated-truth status;
- a fictional header with the exact rendered date-and-shift surface, guards, and unit;
- a coherent no-change flag or one to three occurrence rows;
- clean structured values for item, entry and exit time, description, action, and resolution;
- generator, dataset, seed, split, template, profile, difficulty, font, and degradation
  provenance;
- a `synthetic.surface` view containing the exact text painted onto the image;
- explicit messiness and legibility annotations.

The clean structured values support domain checks. OCR fidelity is scored against the exact
rendered surface, including deliberate blanks or transformations, rather than against text that
was never visible on the page.

Contradictory truth is invalid. A no-change sheet cannot contain occurrence rows; an occurrence
requires non-blank item and description; an exit time requires an entry time; times use the
canonical `HH:MM` form in data.

## Generation and held-out structure

Each document receives its own deterministic random-number generator derived from the dataset
seed and document index. Adding an unrelated generation step therefore does not silently shift
all later documents.

The test split holds out vocabulary, phrase templates, one layout variant, and the upper
degradation band. Train and validation use the lower degradation band. These boundaries reduce
memorization risk, but they do not make the generated distribution representative of real
handwriting.

The renderer chooses `clean`, `scan`, or `photo` difficulty and records every decision in the
ground truth. Five vendored handwriting fonts provide reproducible assets; their identities and
licenses are documented in [`assets/fonts/FONTS.md`](../assets/fonts/FONTS.md).

## Generated tree

Disposable generation writes a complete fresh tree:

```text
data/synthetic/tier_c/
├── pngs/tc-NNNNNN.png
├── pdfs/tc-NNNNNN.pdf
├── gt/tc-NNNNNN.json
├── manifests/train.jsonl
├── manifests/val.jsonl
├── manifests/test.jsonl
└── meta.json
```

The generator writes into a sibling staging directory, validates the result, and then publishes
the tree. A failed run does not mix new files with a previous dataset. `data/synthetic/` is
ignored because those outputs are regenerable developer artifacts.

## Manifest and byte integrity

Each canonical JSONL row has exactly this shape:

```json
{
  "doc_id": "tc-NNNNNN",
  "split": "val",
  "image": "pngs/<doc_id>.png",
  "gt": "gt/<doc_id>.json",
  "sha256_img": "<64 lowercase hex>",
  "sha256_gt": "<64 lowercase hex>"
}
```

Paths are relative POSIX paths confined to the dataset root. Absolute paths, backslashes,
parent segments, duplicate IDs, duplicate paths, extra keys, wrong split counts, non-PNG image
signatures, and malformed ground truth are rejected before evaluation.

`sha256_img` covers the exact PNG bytes read by OCR. PDF is a derived convenience artifact and
is not the canonical image identity because its writer can add variable metadata. `sha256_gt`
covers canonical ground truth without the storage-only `source_file` field.

JSON and JSONL use UTF-8, LF endings, sorted keys, finite numbers, and deterministic separators.
Metadata and manifests are published atomically.

## Validation freeze

The external freeze for the 45-entry `bench-balanced/val` split is:

```text
data/manifests/tier_c_manifest_v2/bench-balanced.val.jsonl
```

Its canonical SHA-256 is
`aa317c587a71e51c7352dd1379412a1e00c222494e3e112f038256ab316986bd`.
The loader compares the generated manifest with that independent file and then verifies every
PNG and ground-truth hash. Generation and evaluation never create or update the freeze.

## Local developer commands

Generate a disposable canonical set:

```console
make gen-sheets DATASET=smoke
make gen-sheets DATASET=bench-balanced
```

Run a non-release local evaluation against a generated validation split:

```console
make eval-synthetic DATASET=smoke SPLIT=val VISION=local_ocr DPI=150
```

Local evaluator details belong under `private/audit/` or another ignored output directory.
Evaluators never write directly to `docs/`; publication is a separate write-once operation
described in [`EVAL_RELEASE.md`](EVAL_RELEASE.md).

## Privacy and interpretation rules

- Never add a real scan to the generator, corpus, sample set, or ground truth.
- Treat a coincidental fictional identifier collision as a review event, not permission to
  publish real context.
- Run `make privacy-check` before committing generated assets or metadata.
- Publish aggregate release evidence only through the validated publisher.
- State the dataset, split, count, commit, reader, language pack, and runtime with any result.
- Describe safety gates as fail-closed behavior on this corpus, not general OCR accuracy.
